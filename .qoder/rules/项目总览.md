# 项目总览：规则体系说明与接入

> 本文件覆盖：规则文件的组成与分层、接入映射与步骤、接入档位、规则自检清单与维护方式。
> 给谁用：首次把规则体系装进新项目、增删规则文件，或需要核对规则集合是否一致时加载。

## 定位

规则分入口、通用流程与语言专项三层；跨层按任务导航引用，不重复定义约束。规则是提示上下文，不是自动运行的状态机，质量门禁须由实际命令、CI 和权限机制执行。

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 入口 | `工程总纲.md` | 唯一规则索引、授权边界、安全基线与冲突处理 |
| 入口 | `AI编码代理指令.md` | 安装为 `AGENTS.md`：项目配置来源、命令入口与红线 |
| 语言无关 | `AI工作流规范.md` | 变更分级、冷启动、七步流程、交付证据 |
| 语言无关 | `Git工作流规范.md` | 提交、分支、PR/MR 与 CI 治理 |
| 语言无关 | `架构决策记录.md` | ADR 触发条件、状态机与模板 |
| 语言无关 | `文档规范.md` | 文档权威来源、目录职责、更新触发条件 |
| 语言无关 | `项目结构规范.md` | 目录结构、模块边界、命名与 .gitignore |
| C++ | `C++项目规范.md` | 语言、并发、命名、注释、接口导出与自测钩子 |
| C++ | `C++构建与依赖规范.md` | CMake、构建类型、依赖治理、工具链与 CI 门禁 |
| C++ | `测试规范.md` | 测试框架、目录、必测场景、覆盖率与钩子登记 |
| 说明 | `项目总览.md` | 本文件：接入步骤、档位与自检 |

更换语言栈时替换 C++ 层三份文件，并同步修改索引、触发方式及通用文件中的目录示例和专项引用；不假定其他文件完全无需调整。

## 接入映射

本目录是模板源，接入后规则文件与入口文件分处两地：

| 本目录文件 | 目标位置 | 说明 |
| --- | --- | --- |
| 除 `AI编码代理指令.md` 外的 10 份 Markdown 文件 | `.qoder/rules/` | Qoder 按 frontmatter 触发方式加载 |
| `AI编码代理指令.md` | 项目根 `AGENTS.md` | 标准入口，只维护这一份 |

目标项目不再另存同内容的中文入口。迁移旧双入口时先核对差异、合并项目配置，再经授权移除副本；不得覆盖已有 `AGENTS.md`。入口里的规则路径以项目根为基准，规则之间的文件名相对规则目录。

Qoder 支持自动识别项目根 `AGENTS.md`；其他工具按其官方机制适配，不承诺中文文件名或 Qoder 的 frontmatter 在所有工具中自动生效。不支持时显式指定入口，并按索引读取所需规则。

## 接入步骤

1. 按映射安装全部规则；已存在规则或入口时先比较并合并，保留项目专属配置，不直接覆盖。
2. 在根目录 `AGENTS.md` 填写配置来源、真实命令入口、本地验证授权、环境要求、红线与不可修改范围；已有命令和精确版本继续在其原有权威配置维护。
3. 无额外红线时明确确认；不适用的验证项注明原因。缺失项仅在影响本次安全或验收时阻塞，不反复追问无关配置。
4. 小项目以 README 与 `AGENTS.md` 为入口，不要求创建 `docs/`。跨会话任务、架构或接口知识出现后，再按 `文档规范.md` 创建必要文档。
5. 目录按现有项目和实际模块建立，不照抄全部骨架；直接集成第三方库时维护 `third/README.md`。
6. 完成下方自检，并在目标工具确认规则可见和任务触发情况；文件已安装不等于当前会话已加载。

## 安装与使用深度

统一完整安装、按需加载，不再提供引用不完整的“最小文件集”。小项目通过简化流程和减少文档控制成本，不通过删掉被引用的规则控制成本。

- 小型局部任务：总纲、工作流与必要专项规则；不强制 ADR、项目摘要或任务文件。
- 多模块或高风险任务：额外读取对应的结构、ADR、Git 与文档规范。
- 确需删除专项规则时，必须同步调整索引、入口和所有引用，并验证自检；这是定制版本，不属于默认接入。

## 加载预算

Qoder 官方 Rules 文档说明：所有已激活规则合计最多 100,000 字符，超出内容会截断。模板自检采用“全部规则加入口”的保守上限，同时报告常驻规则字符量；这不等于实际会话 token 用量，也不保证其他工具使用相同预算。

- 常驻（always_on）只保留 `工程总纲.md` 和 `AI工作流规范.md`；Git 细则改为 model_decision，操作授权边界留在总纲。
- 语言、构建与测试规则用 glob；纯设计、运行命令等没有文件匹配的任务，按总纲索引显式补读对应规则。
- 其余用 model_decision，`description` 写明触发信号。按节导航便于阅读，但不会自动减少已注入的整份规则文本。
- 新增规则先考虑合并或删除已有重复内容；优先记录项目特有约束、默认值及例外，避免重复语言教程。

产品说明来源：<https://docs.qoder.com/user-guide/rules.md>

## 规则自检

规则本身也会腐化，且腐化方式是静默的——索引指向已删除的文件、引用路径写错、同一规则出现两个版本。增删规则文件、调整 `trigger` 或修改索引后，逐项核对：

- [ ] `工程总纲.md` 索引表中的每个文件都存在，且目录中没有未登记的规则文件；
- [ ] frontmatter 已闭合，`trigger` 合法且与索引一致；glob 有非空模式，model_decision 有适用场景描述；
- [ ] 规则引用与安装后入口可达；项目文档引用区分真实文件、约定位置与代码示例；
- [ ] 全部规则加入口的保守字符预算未超限，并检查常驻内容是否可精简；
- [ ] 同一约束只有一个定义处，摘要未增加限制；示例与规则语义一致。

本仓库自检校验结构、规则引用和预算，不证明命令已配置、示例可编译或规则已被工具加载。项目自定义文档和代码示例的有效性、语义冲突及实际触发仍须人工或专项测试确认。

## 维护方式

- 规则变更走正常提交：一次提交只改一类规则，类型用 `文档`；红线变更需审批并单独提交。
- AI 修改规则须有用户请求或明确授权；用户已要求修复规则时无需重复确认。完成后验证并评审，但不因此自动获得提交或推送权限。
- 新增规则前先确认字符预算，并优先扩展已有章节而非新建文件；新建文件必须登记索引并分配 `trigger`。
- 接入、相关配置/依赖变化或发现规则失真时复核受影响条款；定期复核由维护者按需安排，沿用现有任务或评审记录，不另建登记表。
- 规则与实现冲突按 `工程总纲.md` 处理：区分事实与约束，查明差异后再经授权修正相应一方。

## 常见错误

- 只复制入口而不复制规则目录，或误以为中文入口文件名会自动加载；
- 不核对目标项目配置，拿模板命令或版本当作已验证事实；
- 完整安装后仍在每次任务中主动读取全套，或为小项目生成全部文档；
- 直接改写已采纳 ADR 的正文去“同步现状”，破坏决策追溯；
- 在多个文件里各写一份同一规则，改一处漏一处。
