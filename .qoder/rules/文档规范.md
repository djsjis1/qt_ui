# 文档与项目知识治理规范

> 本文件覆盖：文档权威来源、目录与职责、模型友好写法、当前态文档的更新触发条件。
> 给谁用：变更可能影响项目知识、架构、发布说明或 AI 会话摘要，或需创建/更新/审查文档时加载。

## 定位与权威来源

文档保存可验证的项目知识，不为流程生成文本。

| 信息 | 权威来源 | 用途 |
| --- | --- | --- |
| 实现行为、构建和测试结果 | 代码、CI、Git 历史 | 事实核对 |
| 工作目标、进度、阻塞与验收 | 已配置的外部项目系统；否则 `docs/tasks.md` | 任务追踪 |
| 长期设计取舍及理由 | `docs/adr/ADR-*.md` | 决策追溯 |
| 当前架构、模块、接口和运维方式 | 架构/API/模块/部署文档 | 项目当前态 |
| 用户可感知或发布相关变更 | `docs/changelog.md` | 发布沟通 |
| 会话恢复的简明入口 | `docs/project_context.md` | 非权威摘要与导航 |

实现事实与规范要求分开核对，冲突处理见 `工程总纲.md`；任务状态以已配置的外部系统或 `docs/tasks.md` 为准。只读分析/评审不自动写文档；以下维护要求适用于已获授权的实施任务。

## 文档结构与职责

```text
docs/
├── project_intro.md         # 项目介绍：目标、用户、边界、技术栈概览
├── project_context.md       # AI 会话摘要入口，非权威
├── architecture.md          # 当前系统边界、依赖、数据流
├── modules.md               # 当前模块职责与扩展点
├── class_reference.md       # 公共类/组件参考（按项目需要）
├── api.md                   # 对外 API（按项目需要）
├── protocol.md              # 协议定义（按项目需要）
├── database.md              # 数据模型与迁移说明（按项目需要）
├── deployment.md            # 部署、升级与回滚（按项目需要）
├── troubleshooting.md       # 已确认问题与处置方式（按项目需要）
├── changelog.md             # 发布或待发布变更摘要
├── test_hooks.md            # 测试钩子清单（存在钩子时）
├── adr/                     # 长期决策及理由
└── tasks.md                 # 进行中任务的恢复要点（仅需要时创建，见下文）
```

目录按项目适用性创建，禁止为了齐全而创建空文档。

小项目只需项目根 `README.md` 与 `AGENTS.md`，已有文件可以承担下表职责，不要求增加固定文件名：

| 文件 | 使用条件 | 写什么 |
| --- | --- | --- |
| 项目根 `README.md` | 默认项目说明 | 项目目标、使用与构建入口 |
| `AGENTS.md` | 代理入口 | 配置来源、命令导航与项目边界 |
| `docs/project_intro.md` | README 面向用户，确需独立内部介绍时 | 内部目标、模块导航；不复制版本或命令 |
| `docs/project_context.md` | 多会话/多模块导航确有价值时 | 高价值状态摘要与权威来源链接 |

### 项目介绍（project_intro.md）

需要独立介绍时，只补充 README 未覆盖的目标、用户边界及模块导航。精确版本指向构建/依赖配置，命令指向现有 README、脚本或 `AGENTS.md`；不再复制一份。

### 模块介绍（modules.md）

每个模块至少包含：

- 模块职责：一句话说清楚这个模块干什么
- 公共接口：对外暴露的关键类/函数/接口
- 依赖关系：依赖哪些其他模块、被哪些模块依赖
- 扩展点：如何新增功能而不破坏边界

### 模型友好原则

文档设计应考虑 AI 模型的阅读效率：

- 优先使用结构化格式（表格、列表、标题层级），避免大段连续文本。
- 长文档应在开头提供摘要或目录，关键结论前置。
- 同一信息只在一个地方维护，其他地方用链接引用，避免多处同步更新。

## project_context.md：项目仪表盘

`project_context.md` 是可选的会话恢复导航，不代替 `AGENTS.md` 或 README。仅在确有长期导航需求时建立；摘要指向权威来源，不复制任务进度、命令和架构全文。可使用：

```markdown
# 项目仪表盘

> 本文件是可选会话导航；事实与状态以所链接的来源为准。

## 项目一句话
<!-- 这个项目做什么，给谁用 -->

## 当前导航
- 优先任务：链接外部任务系统或 tasks.md（如存在）
- 关键阻塞：一句话与来源链接（如存在）

## 关键约束提醒
<!-- 只写容易踩坑的：红线、兼容性、发布窗口等。没有就写“无特殊约束” -->

## 关键决策
- ADR-XXX：一句话结论

## 项目入口
- 项目说明：../README.md
- 命令与配置导航：../AGENTS.md
- 架构或模块文档：仅链接实际存在的文件

## 最近核对
- 日期：YYYY-MM-DD
- 依据：关联 PR、发布或文档链接
```

更新时机统一见「会话结束检查」。普通进度、实现细节与未批准方案不抄入摘要；每次更新保留核对依据。摘要与权威来源冲突时核对来源并修正摘要，不因此改变规范要求。

## docs/tasks.md：进行中任务

只有确实需要跨会话恢复且未配置外部任务系统时，才创建 `docs/tasks.md`。单会话工作不因有风险或验收条件就创建。仅保留目标与验收、进度、已验证事实、下一步、阻塞；并行任务使用独立编号分节，不能相互覆盖。

任务完成后先将需长期保留的决策、运维知识或遗留风险移到对应权威记录，再清理已完成条目；全部结束时可在已授权范围内移除文件，不删除其他任务或未解决的风险。已有项目摘要时更新导航，不能仅因创建任务文件就强制新建摘要。

## 会话结束检查

实施任务结束前（或需跨会话交接时）核对相关文档，不强制写入。已存在项目摘要且命中以下条件时更新；没有摘要时先判断现有 README、任务记录或 ADR 是否已经足够：

- 当前优先任务新建、替换或清除（`docs/tasks.md` 创建或删除）；
- 出现新的关键阻塞或风险，或原阻塞已解除；
- ADR 被采纳、替代或废弃，导致关键决策变化；
- 当前架构或关键约束发生变化。

上述条件都未命中时不修改本文件，也不为了“留痕”只改「最近核对」日期——那属于流程产物，不是项目知识。

与 `AI工作流规范.md` Step 4 的关系：Step 4 只说明何时识别文档影响；触发条件、权威文档映射与会话结束检查以本节为唯一来源，其他文件不再重复。

## 更新决策与自动维护

AI 在 `AI工作流规范.md` Step 4 识别文档影响，在 Step 6 核对，在 Step 7 交付结论中给出证据。以下为最小映射：

| 触发条件 | 必须更新的权威文档 | 可选或衍生更新 | 交付证据 |
| --- | --- | --- | --- |
| 项目目标、用户边界或技术栈变化 | README 或已有 `project_intro.md`；技术栈事实在构建/依赖配置维护 | 入口导航、已有项目摘要 | 变更点 |
| 模块边界、依赖、数据流或架构变化 | `architecture.md` / `modules.md` | `project_intro.md`、图表、项目摘要、ADR | 变更点和关联 ADR |
| 公共 API、协议、数据模型或兼容性变化 | `api.md` / `protocol.md` / `database.md`（按适用） | Changelog、项目摘要、ADR | 版本/迁移/兼容性说明 |
| 长期设计取舍被采纳、替代或废弃 | ADR、ADR 索引及受影响的当前态文档 | 已有项目摘要 | ADR 编号和落地文档 |
| 部署、升级、回滚或运行依赖变化 | `deployment.md` | README、Changelog、项目摘要 | 操作与回滚验证 |
| 新增/删除测试钩子 | `test_hooks.md` | 项目摘要（仅关键约束变化时） | 钩子和关联用例 |
| 用户可感知、发布相关或兼容性影响变更 | `changelog.md` | README、项目摘要 | 发布条目或待发布分组 |
| 已建立的跨会话任务状态变化 | 外部任务系统；未配置时为 `docs/tasks.md` | 已有项目摘要（仅关键导航变化时） | 状态与证据 |

表中文件名是默认职责位置，项目已有等价文档时更新原处，不额外建副本。未触发时不创建文档、不必说明未更新理由；触发后无法更新或决定豁免时才说明依据与剩余影响。

## Changelog 与版本关联

Changelog 服务发布沟通，不是 Git log 的副本。仅记录：用户可感知的功能/修复、升级或部署影响、兼容性/安全说明、弃用或破坏性变更。内部重构、测试、格式化和普通维护默认不逐条记录，除非项目发布策略另有规定。

优先在 PR 合并、发布准备或版本发布时按变更组聚合；不要求 AI 为每次提交自动新增条目。条目至少说明版本或“未发布”、日期（发布时）、变更摘要、影响/迁移信息以及关联 PR/ADR（如适用）。接口版本以 `api.md` 为准，Changelog 只做摘要和链接。

## 例外、债务与质量

紧急修复可先恢复服务，但必须在同一 PR 或 `docs/tasks.md` 中记录缺失文档、负责人和关闭条件。原型阶段或确实不适用的文档可不创建，但应在 ADR、任务文件或项目摘要的适当位置说明原因；不使用未定义的“下个迭代再补”。

文档正文使用中文，标识符和 API 字段保留原始英文。架构、流程和时序图优先使用 Mermaid；示例必须与真实接口一致。禁止复制代码充当文档、以截图替代可维护图表，或声称文档已同步却未说明更新项或不适用原因。
